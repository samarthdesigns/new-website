The Problem

I joined the pre-sales team, the group that builds demos and experiences for client proposals. The work was good. It just never added up.

Every demo was built in a silo, shaped so tightly around one client that reusing it meant starting over. Nothing looked the same from one proposal to the next, and designers kept rebuilding patterns someone had already made.

WHAT WE NEEDED

One source of truth that could work as a product line and still fit any client or proposal.

Role and constraints

My role

Product Designer. I owned the system end to end, from research through rollout, and then each AI version after it.

Deadlines every week

Pre-sales runs on proposal dates. Whatever I built had to make the next demo faster, not hold it up.

One brand, many clients

Demos had to stay on the company's brand, and still look like the client's own product when a deal needed that.

Research

I spent six months on research before the system took shape.

Designers

I interviewed designers about where demo work hurt. The system is built on what 50+ designers told me, covering about 10 years of their work.

Existing systems

I reviewed existing design systems to decide what we could plug in, what we could modify, and what we had to build ourselves.

Brand

I worked with marketing on the company's brand vision, so the system would be on-brand from its first release.

WHAT IT SHOWED

Different clients, same patterns, rebuilt from scratch every time.

The decision

A system first, demos second

I built an MVP, then spent six months building it out and several more months in feedback sessions with designers. The cost was time: months of system work on a team that sells every week. I made that call because faster one-off demos would only have made more of the problem.

One parent, many children

Voyage is the parent system. Teams build child systems that add or change components for their own work, and weekly feedback sessions merge the useful changes back into Voyage. That kept teams inside the system instead of working around it.

What it covers

Brand philosophy, components in depth, usage guides, and the reasoning behind each decision.

Direction

Fonts, colors, illustrations, data visualizations and content, so a demo reads as one product.

Version one

Every demo became reusable across proposals. Design turnaround dropped 30%, and the output finally looked consistent. Five or more teams adopted it.

White-label by toggle

Sales kept asking for demos in the client's own look. So I added fast switching between versions and themes: white-label by default, styled per client when a deal needs it. What used to be a rebuild became a toggle.

When designers left Figma

With AI, designers started building outside Figma, in Claude Code, Copilot, Claude Design and other tools. The system had to follow them there.

Version two: AI support AI-assisted

Contracts

Every component and every group of components got a contract: what it is for and the rules it follows.

Context files

Context docs explain how to use each component. A context markdown file explains why it exists, so an agent can reason about it.

Developer versions

Every component was translated into a stack-agnostic developer version, so any AI tool can build experiences that match.

It helped, but AI output still drifted away from the system. Documentation alone was not enough.

Voyage AI

So the next version added a plugin and process contracts for every AI tool. The rule is simple: reuse first, write down what's missing, and let a human decide what gets built.

Output

Screens built with Voyage across products. One of them was made with the AI flow above.

The result

Deals supported in one year$500M+
Biggest deal won$100M+
Proposals from my team3/mo → 3/wk
Teams using it5+

Designers now build experiences with AI without the drift, and the system keeps itself maintained through the same flow. Clients this touched include Wells Fargo, JPMorgan Chase, Morgan Stanley, Charles Schwab, BlackRock, Corebridge and FedEx.

What I learned

Docs don't stop drift. Process does.

Version two had contracts and context files, and AI still drifted. What worked was making reuse the only path and putting every gap in front of a person.

A system has to let teams change it

Child systems and weekly merges let teams change Voyage for their own work without leaving it.
